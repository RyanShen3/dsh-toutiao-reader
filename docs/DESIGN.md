# 设计：三级抓取策略

## 为什么三条路

- **direct-fetch**：静态页最快（~1s），但头条静态 HTML 必命中反爬，只当试探
- **Edge CDP 常驻**：真浏览器渲染，头条默认通道；常驻端口 9333 复用进程与标签页
- **dump-dom 兜底**：CDP 不可用时一次性渲染，最慢但保底

## 关键机制

1. 域名缓存：直连试探失败即记为 `browser`，解过一次记为 `solved`（跳过质询宽限窗）
2. 质询宽限：首见域名等到正文后留 1.2s 等 reload 再取干净文本
3. 标签页复用：`%TEMP%/webfetch-tab.id` 记住常驻标签页，省 ~4s
4. 提速：CDP 阶段禁图 + 屏蔽字节跳动 CDN（pstatp/byteimg/snssdk）
5. 协作取消：轮询循环观测 AbortSignal，取消快速退出

## 与工作区脚本的关系

核心逻辑与 `tools/webfetch.mjs` 同源，且共享常驻浏览器文件（pid/tab/profile），
脚本与插件互不干扰、互相加速；脚本保留为插件不可用时的后备路径。
